## 版本一：精简版（推荐，适合一页简历）

**CodeBot — 轻量级终端 AI Coding Agent** | Python · 个人项目 | GitHub: github.com/1144zhang/terminal-codebot

**项目描述**：基于 ReAct + Plan Mode 双模式驱动的终端 AI 编程助手，采用交互/引擎/工具/记忆/安全五层分层架构，兼容 Anthropic / OpenAI 双协议，支持 MCP 工具扩展与多 Agent 并行协作，约 1.5 万行 Python。

**技术栈**：Python 3.11+ · Textual(TUI) · Anthropic SDK · OpenAI SDK · Pydantic v2 · Qdrant · asyncio · pytest

**技术亮点**：
- 设计 ReAct 推理-行动循环（Think→Act→Observe→Loop），用 `asyncio.Future` + `await` 实现非阻塞式人工权限确认，TUI 动画与用户交互不卡顿；通过策略模式 + 独立序列化层统一适配三种 LLM 协议（Anthropic Messages / OpenAI Responses / Chat Completions），切换模型零代码改动
- 构建六层纵深安全防御（Plan 模式例外 → 安全白名单 → 危险命令正则黑名单 → 路径沙箱符号链接解析 → 规则引擎 → 权限模式矩阵 → 人工确认），通过短路求值的管道模式实现纵深防御，有效拦截 `rm -rf /` 等危险操作
- 落地代码 RAG 系统：用 AST 按函数/类分块（Python）+ Qdrant 向量库（嵌入式模式）+ 自实现 BM25 + RRF 混合检索 + mtime/hash 两级增量索引，解决"用户说登录鉴权、代码叫 verify_token"的词汇鸿沟问题；全链路渐进式降级，embedding/向量库不可用时自动回退关键词搜索，零阻塞主流程
- 设计双层上下文压缩（工具结果裁剪 + LLM 结构化摘要）+ RecoveryState 文件快照恢复 + 断路器防频繁压缩，支持单次对话上千轮交互不超 20 万 token 上限；五大正交扩展机制（Tool / Skill / MCP / Hook / SubAgent）互不耦合，独立演进

## 版本二：详细版（适合作为主打项目，项目占 1/2 篇幅）

**CodeBot — 轻量级终端 AI Coding Agent** | Python · 个人项目 · ~15,000 行 | GitHub: github.com/1144zhang/terminal-codebot

### 项目概述

一个住在终端里的 AI 程序员——用户用自然语言下达任务（"修复这个 bug""给模块写测试"），Agent 自主完成读文件、搜代码、精确编辑、跑命令验证、循环迭代直至完成。区别于补全型工具（Copilot），这是完全自主的 Agent。采用交互层 / 引擎层 / 工具层 / 记忆层 / 安全层五层分层架构，兼容 Anthropic、OpenAI 双协议，支持 MCP 工具扩展、Skill 技能包、跨会话记忆、多 Agent 团队协作。

### 技术栈

Python 3.11+ · Textual(TUI 框架) · Anthropic SDK · OpenAI SDK · Pydantic v2 · Qdrant(向量库) · asyncio · PyYAML · HTTPX · pytest · uv

### 核心技术亮点

**1. Agent 引擎：ReAct 循环 + 异步权限确认**
- 实现 ReAct 推理-行动循环（Think→Act→Observe→Loop），支持 max_tokens 三层恢复策略（提升上限 → 提示继续 → 分解任务），连续 3 次幻觉工具调用自动终止
- 用 `asyncio.Future` + `await` 实现非阻塞式人工权限确认：Agent 协程挂起等待用户决策，事件循环继续调度 TUI 动画，避免同步阻塞导致 UI 冻死
- 工具调用按 `is_concurrency_safe` 分区并发执行（只读工具 `asyncio.gather` 并发，写工具串行），读多文件只需最慢一个的耗时

**2. 多协议适配：策略模式 + 独立序列化层**
- 定义 `LLMClient` 抽象接口（仅一个 `stream()` 方法），三个实现类各自负责 Anthropic Messages / OpenAI Responses / Chat Completions 协议的请求序列化与流式事件映射，切换模型仅改一行配置
- 独立 `serialization.py` 承担内部统一格式 ↔ 各 API 格式转换，客户端类只管"调 API + 翻译事件流"，单一职责
- 不用 litellm 统一层，直接集成官方 SDK，享受 Anthropic Prompt Caching（省 90% 费用）和 Extended Thinking 独有特性

**3. 六层纵深安全防御**
- Plan 模式例外 → 安全命令白名单（40+ 只读命令，禁管道/重定向/命令替换）→ 危险命令正则黑名单（8 类：rm -rf /、mkfs、fork bomb、curl|sh…）→ 路径沙箱（`resolve(strict=True)` 解析符号链接防越狱）→ 规则引擎（三层 YAML + fnmatch 通配）→ 权限模式矩阵（6 种模式）→ 人工确认 HITL
- 短路求值的管道模式：任一层做出"允许/拒绝"立即返回，纵深防御——即使某层有漏洞后续层仍能拦截

**4. 代码 RAG 系统（核心亮点）**
- **AST 语义分块**：Python 用 `ast` 按函数/类切，保证每个 chunk 是完整语义单元；超长函数（>50 行）滑窗二次切分带 overlap；非 Python 文件滑窗兜底
- **Qdrant 向量库**：默认嵌入式模式（本地文件持久化，clone 即用），配置留 `qdrant_url` 开关可无缝切远程集群；用稳定点 ID（`hash(file:name:line)`）+ upsert 实现增量更新，`delete_by_file` 清理删除文件
- **混合检索 + RRF 融合**：向量召回 Top-20 + 自实现 BM25 关键词召回 Top-20，用 RRF（倒数排名融合，`1/(k+rank)`）融合——只看排名天然归一化，无需调参，解决向量分数（0-1）与 BM25 分数（无上界）量纲不一致问题
- **两级增量索引**：mtime 粗筛（一次 stat）+ content_hash 确认（读全文算 md5），避免 touch 误报，只重新 embedding 真正变化的文件
- **全链路渐进式降级**：embedding/Qdrant 任一不可用自动回退 Grep 关键词搜索，46 个单元测试全通过

**5. 长对话上下文管理**
- 双层压缩：Layer 1 每次调用前裁剪超大工具结果（单条 >5 万字符截断）；Layer 2 接近 token 上限时用 LLM 生成 9 段结构化摘要，保留近期 1 万 token 原文
- RecoveryState 缓存文件快照，压缩后作为附件恢复工作上下文，避免 LLM 重复读文件
- Token 混合估算：API 返回精确值锚定 + 锚点后消息字符数÷3.5 估算，无需引 tokenizer 库
- 断路器模式防频繁压缩（60 秒冷却）

**6. 五大正交扩展机制**
- Tool（工具注册表 + Pydantic 自动 Schema 生成） / Skill（Markdown SOP 注入改行为） / MCP（标准协议接外部生态） / Hook（12 种生命周期事件自动触发） / SubAgent（Fork/SubAgent/Teammate 三种模式）——五个维度互相独立，可单独演进

### 项目成果

- ~15,000 行 Python，20+ 内置工具，14 个斜杠命令，4 个内置 Skill，4 个内置子 Agent
- 17 + 46 个单元测试覆盖核心模块与 RAG 链路
- 支持 Claude / GPT / DeepSeek / Qwen / Ollama 等多种模型，无供应商锁定
